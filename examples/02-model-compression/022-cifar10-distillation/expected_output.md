## 2. `--smoke-test` 运行结果（已实测，2026-10-28）

退出码 `0`，原始输出：

```
使用设备：cpu
损失函数梯度自检通过：KL 梯度与解析式一致、Teacher 无梯度、输出形状正确。
网络级梯度自检通过：KD 梯度流入 Student 参数并完成一步更新，Teacher 未受影响。
```

这两条自检各自钉死一个容易写错的地方：

| 自检 | 钉的是什么 | 写错会怎样 |
|---|---|---|
| 损失函数级 | KD 损失对 logits 的梯度必须等于解析式 | 用 `softmax` 而不是 `log_softmax` 再取 log，梯度会多／少一个 softmax 项，损失照样下降 |
| 网络级 | 梯度只进 Student，Teacher 参数一动不动 | 忘了 `requires_grad_(False)`，会把教师也训了，蒸馏变成"两个模型互相迁就" |

`--smoke-test` 不下载数据、不训练，几秒钟跑完，可以作为改动后的回归检查。

| temperature / alpha | 2.0 / 0.7（默认） |
| 训练轮数 | 20 + 20（默认） |

判读方式：

- **看差值，不看绝对值**。CIFAR-10 上 20 轮的小网络，绝对值受种子与增强影响很大；
  同一份学生初值、同一份数据顺序下的 CE vs KD 差值才是本篇的结论。
- 差值为负（KD 更差）在 20 轮短训练里完全可能出现，这本身就是结论的一部分：
  蒸馏的收益依赖教师质量与训练预算。
- 脚本用同一 seed 建两组 DataLoader，并共享一份学生初值——这两点不做，
  CE 与 KD 的对比就没有可比性。

## 4. 这份数据不能说明什么

- **不是 SOTA 复现**：网络是教学规模，没有调参、没有多 seed 平均。
- **不涉及 CUDA kernel**：全程 PyTorch 算子，蒸馏的"加速"是模型变小带来的，
  不是本篇测的。
