# 学习路线：九章

这份课程要回答一个问题：**同一段 AI 计算，为什么换个写法就快了几倍，又为什么有时候一点也不快。**

全书 81 篇，仓库收录其中 52 篇的完整程序。篇目清单见
[文章索引](reference/article-index.md)，每篇的依赖、硬件与实测状态见
[能力矩阵](reference/capability-matrix.md)。

## 怎么用这份课程

三种读法，按你的目标选：

| 读法 | 适用 | 做法 |
|---|---|---|
| **顺序读** | 第一次接触 GPU 编程 | 第 1 章逐篇读，读到第 2 章时已经能自己写 Kernel |
| **按章跳** | 只关心某一环（比如部署或医疗） | 读完第 1 章的 001、003 后直接跳到目标章 |
| **按问题查** | 线上已经有具体现象 | 从 [能力矩阵](reference/capability-matrix.md) 的「验证状态」和「前置」两列反查 |

所有篇目共用同一条叙事结构，读三篇之后就能预判下一篇怎么写：

```
先算一笔账（参数/字节/时间） → 写最小实现 → 用对照证明没算错 → 再看时间花在哪
```

这条结构是刻意的：**任何一个"快了几倍"的结论，都必须先有一个能对上的数。**

## 第 1 章 · 001–019（GPU 编程基础 · `01-gpu-programming/`）

**目标**：GPU 里没有矩阵，只有线程编号和一段连续显存。这一章把"我怎么知道第
`i` 个线程该算哪个数"变成不需要想的事。

**必读三篇**

| 篇 | 为什么必读 |
|---|---|
| 001 | 全书骨架：一个线程算一行点积，前向/`dX`/`dW` 三个 Kernel 同篇对照 |
| 010 | 归约与前缀和：第一次遇到"线程之间要合作"，也是 `__syncthreads` 的入口 |
| 017 | 数据竞争：两代坐标混用不会报错，只会算出一个错误的宇宙 |

**这一章最常见的误解**：以为线程越多越快。006 的 `grid=(7,7)` 会多启动 144 个
线程，靠边界判断挡掉——多出来的线程不是免费的。

**衔接**：第 1 章只谈"算得对不对"；"快不快"从第 7 章开始系统讲。

## 第 2 章 · 020–026（模型压缩 · `02-model-compression/`）

**目标**：把「参数少了」「FLOPs 降了」「文件小了」「跑得快了」这四件事**分开**。

**必读两篇**

| 篇 | 为什么必读 |
|---|---|
| 023 | 参数量缩到 1/106，计算量只降 27%——一篇文章拆掉"小即快"的直觉 |
| 026 | 99.99% 是零的矩阵，用 CSR 压到 8.4 MB；稀疏的代价在索引，不在数值 |

**常见误解**：量化是"把 float 换成 int8 就能加速"。021 会告诉你，反量化之后
卷积仍是 fp32，省的是显存与带宽，不是乘加次数。

## 第 3 章 · 027–035（推理服务与部署 · `03-inference-serving/`）

**目标**：一次请求的时间不是一个数。模型执行、数据搬运、框架调度、排队，
要分得开才谈得上优化。

**必读两篇**

| 篇 | 为什么必读 |
|---|---|
| 028 | 同一模型三条路径（PyTorch / TRT-FP32 / TRT-FP16）同场对照，口径写死 |
| 029 | 把"引擎执行"与"端到端"分开测；两者的差就是拷贝与调度 |

**衔接**：这一章的对照组（028/029）与第 8 章（067–073）是同一件事的两个阶段：
前者问"值不值得换引擎"，后者问"引擎怎么建、怎么跑对"。

## 第 4 章 · 036–041（端侧推理 · `04-edge-inference/`）

**目标**：摄像头为什么"认出人几十毫秒，提醒却晚两秒"。端侧的瓶颈常常是链路，
不是模型。

**必读**：039（本篇无代码，讲的是 CPU / GPU / NPU 之间的算子支持与图切分）。

**常见误解**：设备上有 NPU，模型就会跑在 NPU 上。执行提供者（EP）注册了，
不等于你的算子被它接管——这需要读图切分报告。

## 第 5 章 · 042–051（并行与分布式 · `05-parallel-distributed/`）

**目标**：并发是"有机会重叠"，不是"一定会加速"。这一章把 DP / PP / TP 三种切法
落到 rank 编号与张量形状上。

**必读三篇**

| 篇 | 为什么必读 |
|---|---|
| 047 | AllReduce / AllGather / ReduceScatter 三条原语的语义，用 4 个数讲清 |
| 048 | 两层 TP 的切分与「偏置只加一次」；纯 Python 版给出可核对的 `[12, 6]` |
| 051 | 8 卡 3D 并行：三组 rank 怎么分、全局 batch 乘几 |

**这一章最容易错的地方**：把 TP 的"部分和相加"当成 DP 的"梯度平均"，在同一段
代码里混用两种语义。

## 第 6 章 · 052–059（自定义算子 · `06-custom-operators/`）

**目标**：什么时候值得自己写 Kernel。答案不是"需要更快"，而是"现有实现多做了
一件你不需要的事"。

**必读**：056（eager / torch.compile / 手写扩展三路对照）。它会告诉你：小 N 时
三者打平，大 N 时融合的收益才出现——**手写不一定更快，但一定更可控**。

## 第 7 章 · 060–066（访存与传输 · `07-memory-and-transfer/`）

**目标**：六个可独立验证的机制——显存记账、合并访存、共享内存容量、常量内存
广播、页锁定内存、异步重叠。

**必读四篇**

| 篇 | 机制 | 观察什么 |
|---|---|---|
| 061 | 合并 vs 跨步 | 同样的数据量，带宽差多少 |
| 062 | 共享内存的分块复用 | 收益随规模变大，但容量压 occupancy |
| 063 | warp 内广播 | 收益随重复度 `u` 增大而减小 |
| 065 | 异步传输 | 总时间接近 `max(拷贝, 计算)` 才算真重叠 |

**这一章是全书的"性能中枢"**：第 1 章的 Kernel 为什么快、第 8 章的引擎为什么更快，
答案大多落在这六个机制里。

## 第 8 章 · 067–073（TensorRT 部署 · `08-tensorrt-deploy/`）

**目标**：一条能核对结果的推理链路：导出 → 构建 → 运行 → 计时 → 量化。

**必读四篇**

| 篇 | 为什么必读 |
|---|---|
| 067 | "导出成功"与"数值一致"是两件事，13 组用例才敢说后者 |
| 069 | 引擎能建不等于能跑：形状落实、地址绑定、输出查询 |
| 070 | 1 ms 的推理与 5 ms 的请求之间，差在哪三笔开销 |
| 073 | 剪枝后参数量减半，为什么推理没变快 |

## 第 9 章 · 074–081（医疗影像实战 · `09-medical-imaging/`）

**目标**：三维体积装不进显存时，怎么切、怎么拼、怎么评估。

**必读两篇**

| 篇 | 为什么必读 |
|---|---|
| 077 | 滑窗推理的三个问题：怎么切、重叠怎么融合、结果放哪 |
| 081 | 评估本身是可验证的：Dice 与手算逐位一致，空掩膜记 `null` 而不是 1.0 |

**这一章的诚实边界**：074/078/081 用**合成数据**跑通，验证的是读取、几何门控、
训练链路与评估公式；真实病例的轴方向与间距需要人眼复核。

## 四条贯穿全书的判断

1. **时间要分层**：Kernel-only / 端到端 / 含编译。混着报就是在制造假结论
   （004、028、070 都在反复强调这件事）。
2. **数字要能对上**：每个"快 X 倍"都要能用手算的量级解释；对不上就是测错了。
3. **加速比要能解释**：省的是访存、是启动次数、是精度，还是压根没省——说得出
   机制才算结论。
4. **没跑过的数不填**：仓库里 43 篇的 `expected_output.md` 是待填 runbook，
   这不是缺陷，是纪律。

## 自测方式

不需要显卡就能跑通的检查点，跑通再往下读：

```bash
python3 -m unittest discover -s tests -v                # 仓库级：结构 + 溯源 + 冒烟
python3 examples/05-parallel-distributed/044-gpu-task-dispatch/gpu_task_dispatch.py      # 第 5 章：调度策略
python3 examples/05-parallel-distributed/048-tensor-parallel-linear/tp_split_check.py    # 第 5 章：TP 切分 → [12, 6]
python3 examples/05-parallel-distributed/051-parallel-group-check/parallel_groups_check.py  # 第 5 章：3D 并行 → PASS
python3 examples/09-medical-imaging/079-ct-amp-check/fp16_numpy_check.py            # 第 9 章：FP16 三条边界
```

其余章节的检查点写在各自 `expected_output.md` 的「判读方式」里——那里列的是
**跑完之后该盯哪个数**，而不是"跑通了"三个字。
