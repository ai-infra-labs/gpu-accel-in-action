- 255 / 256 / 257 是线程块边界，三条线一起看才能确认 `grid` 向上取整没漏线程。

  它的耗时不一定低于手写 kernel——这正是"高级 API 不等于更慢/更快"的观察点。

## 4. 这份数据不能说明什么

- **不能说明剪枝后推理变快**：这里只测"把权重置零"这一步，置零之后矩阵仍是
  稠密的，乘加次数一个都没少。推理侧的账在第 073 篇。
- **编译不计入计时**：`SourceModule` 在采样之外，`torch_prune_roundtrip_demo.py`
  的 `measure()` 也先 `warmup=10` 次。这些是稳态数字，不是冷启动数字。
- **`torch` 侧的模型每次都重建**：`build_model()` 在停表之前调用，但模型构建本身
  包含 H2D，若机器状态不稳定，p95 会明显漂移。
