## 2. `sliding_window_toy.py` 运行结果

退出码 `0`，原始输出：

```
PASS: 32种合成组合；覆盖、加权归一化、短轴补齐与裁回；复数拒绝；窗口分歧融合与高斯权重手算。
overlap 0 每轴窗口 3 三维总数 27
overlap 0.25 每轴窗口 4 三维总数 64
overlap 0.5 每轴窗口 5 三维总数 125
overlap 0.75 每轴窗口 8 三维总数 512
```

四个 overlap 对应的窗口数（单轴 → 三维）：

| overlap | 每轴窗口数 | 三维窗口总数 |
|---:|---:|---:|
| 0 | 3 | 27 |
| 0.25 | 4 | 64 |
| 0.5 | 5 | 125 |
| 0.75 | 8 | 512 |

这组数字可以直接手算核对：窗口 `96`、轴长 `125`（`111` 补齐到 `125`），
`step = max(int(96×(1-overlap)), 1)`，起点从 `0` 走到 `125-96=29`，末尾不足一步时
贴住末端再补一窗。`overlap` 从 0 到 0.75，窗口总数从 27 涨到 512——**19 倍**。
这就是"重叠越平滑，计算越贵"的定量版本。

输出里的 `PASS` 覆盖六件事：

1. 32 种合成组合的覆盖与归一化
2. 短轴补齐与裁回（末轴 95 < 窗口 96）
3. 复数输入被拒绝
4. 窗口分歧时的融合结果
5. 高斯权重的手算值
6. 单幅、单通道的输入约束

## 4. 这份数据不能说明什么

- **不是分割效果**：假预测器输出 `[-x, x]`，与实际器官无关。
- **不是性能数据**：NumPy 版只验证算法口径，没有任何 GPU 计时。
- **没验证真实显存**：窗口数量涨到 512 意味着计算量涨 19 倍，但是否放得下
  取决于 `sw_batch_size` 与模型大小，本脚本不测显存占用。
