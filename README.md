# 大模型训练与推理加速实战

> 仓库标识 `gpu-accel-in-action`（2026-10 由 `cuda-kernels` 更名：原名只覆盖 kernel，装不下压缩/部署/医疗等章节）

**81 篇问题驱动的 CUDA 与 AI 系统长文。** 每篇从一个具体的「为什么」出发，
用能跑起来的代码和能对上的数字回答它——不堆 API，不讲语法，只讲这台机器到底发生了什么。

> 为什么 GPU 有几千个核，程序还是在等？
> 为什么模型参数没多大，训练还是爆显存？
> 为什么权重删了一半，推理一点没快？

这些是专栏的标题，也是专栏的目录。

## 这套专栏在讲什么

不是「CUDA 入门教程」，是**性能归因**：同一段计算，为什么换个写法快几倍，
又为什么有时候一个点也不快。

读者对象很具体：会 Python、写过 PyTorch、能把模型跑起来，
但说不清「GPU 利用率 30% 到底是卡在哪一层」的人。读完之后，你应该能对着一段
Kernel 或一条推理链路，指出瓶颈在访存、在同步、在启动开销，还是在排队。

全书 **81 篇、约 132 万字符**，平均每篇 1.6 万字，含 **1177 个代码块**
（中位数每篇 11 个）。**72 篇的标题就是一个问句**，正文负责把它答完。

## 一篇文章长什么样

同一套叙事结构，读三篇就能预判下一篇：

1. **先给结论，再给推导。** 开篇直接说清「这一篇要拆的是哪一笔账」；
2. **先算数，再写代码。** 数据量、线程数、访存次数先落纸面，再谈实现；
3. **最小实现跑通，再做对照。** 有 naive 版做基准，才敢说优化版快在哪；
4. **把时间拆开。** Kernel 时间、拷贝时间、调度时间混着报就是在制造假结论；
5. **给验证方式。** 约 30 篇专设验证小节（「怎样证明」「怎么核对」）——正确性不能靠「能跑」；
6. **附参考资料与检索日期。** 71 篇文末列出出处（NVIDIA 文档、论文、库版本）。

代码不是装饰：81 篇里有 53 篇带完整程序，都能在配套仓库 `examples/` 下找到对应文件，与文章里的代码块**逐字一致**（md5 对账）；其余 28 篇只给讲解片段，不单独成文件。
