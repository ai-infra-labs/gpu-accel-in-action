判读方式：

- **最后一行没出现就是没通过**。前面的误差行只是打印，判定靠 `assert`：
  形状不一致、出现 NaN/Inf、误差超限，都会直接抛异常。
- **动态引擎要多看一步"8→1"**：脚本刻意把 batch 从 8 切回 1。
  只在第一次落实形状的写法在这一步会报"输出形状不对"或地址越界。
- **误差量级**：FP32 引擎对 FP32 参考，应在 `1e-6` 量级；FP16 引擎在 `1e-3`。
  如果是 `1e-1`，先怀疑参考与引擎的输入不是同一份数据（例如忘了同步 H2D）。

## 3. 三类报错分别是什么

| 报错 | 真正原因 | 本篇怎么避开 |
|---|---|---|
| `set_input_shape` 之后再查询仍拿旧形状 | 形状已落实但没重新查输出 | 每次设形状后重新 `get_tensor_shape` |
| `[TensorRT] ERROR: ... invalid device pointer` | 绑定的地址还指向上一个 batch 的缓冲区 | 每轮重新绑地址 |
| 输出全是 0 / 首帧正确后面全错 | 复用了第一次的 host 缓冲区，没重新 H2D | `infer()` 里每次都拷贝 |
