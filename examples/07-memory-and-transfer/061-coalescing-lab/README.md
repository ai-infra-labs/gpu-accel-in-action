# 061 · 同样搬一张表，GPU 为什么还要看访问方式？

同样的数据量、同样的线程数，耗时能差好几倍——差别不在算法，在**访问模式**。
一个 warp 的 32 个线程读连续地址时，硬件合并成少量内存事务；读跨越不同行时，
事务数按线程数放大。

本篇用 Numba CUDA 对比行连续拷贝与转置读取，三个规模梯度各测一遍。

## 运行

```bash
python -m pip install -r ../../requirements/advanced.txt
python coalescing_lab.py
```

脚本无参数，内部遍历 `(512, 768)`、`(2048, 3072)`、`(4096, 6144)` 三个规模，
每个规模先做正确性校验再计时。

## 环境要求

- 必须：NVIDIA GPU + `numba` 与 `numba-cuda`
- 依赖层：`requirements/advanced.txt`
- 脚本会打印 `version("numba-cuda")`，缺包时这一行会先失败

## 观察点

- 合并与跨步的带宽差多少；跨步访问掉到 1/8 左右是这类实验的典型值。
- 两者算的是同一批数：速度差只能来自访存事务数，不是计算量。
