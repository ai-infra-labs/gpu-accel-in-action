# 溯源契约：代码凭什么可信

这个仓库的每份代码都要能回答一个问题：**它从哪来、验没验过、成熟到什么程度。**
三件事分开看，别混成一句「已入库」。

| 维度 | 回答什么 | 记录在哪 | 谁来保证 |
|---|---|---|---|
| **内容关联** | 有没有对应教程、对应哪一篇 | `blog/NNN-*.md` 的代码块 ↔ `examples/<章>/<篇号-短名>/` 的文件 | 机器：代码块 md5 对账 |
| **运行验证** | 跑没跑过、在什么环境、结论覆盖到哪 | 每篇 `expected_output.md` 首行的 `**状态：…**` | 只能由真实运行产生 |
| **项目成熟度** | 是讲解片段、可跑示例，还是完整工程 | 代码放在哪个区，见下表 | 分区规则 + `standalone` 登记 |

## 三类代码，三种合格标准

| 位置 | 是什么 | 合格标准 | 机器校验 |
|---|---|---|---|
| `examples/<章>/<NNN-短名>/` | 某篇教程的逐字代码 | md5 命中该篇代码块，或按顺序拼自多块 | `scripts/build_from_blocks.py` |
| `projects/ct-reconstruction/` | 完整工程 | 自己能构建、能跑出结果 | 声明 `built_by`，`make strict` 检查入口存在 |
| `cuda_kernels/` | 仓库内加载工具 | 不复制任何篇目源码 | 排除在溯源检查外 |

**为什么完整工程不要求「有对应文章」**：能不能构建、能不能跑出正确结果，和有没有人为它写过一篇博客，是两件互不相干的事。把两者绑在一起，会让「还没写文章」看起来像「代码不合格」。反过来，一篇教程里的代码即使与博文逐字一致，**也只是说明它没跑偏，不说明它跑对过**——后者只认 `expected_output.md`。

## 两个硬规矩

**1. 没实测的代码，必须标注「未实测」。**

仓库不接受「看起来能跑」。凡是没在真实 NVIDIA GPU 上运行过的，`expected_output.md`
里明确写未实测，一个数字都不许填。宁可空着，不能编。

**2. 篇目代码与教程逐字一致。**

每篇的 `README.md` 记着来源（教程文件名 + 代码块序号 + md5）。改了仓库代码必须同步回教程，
否则读者照教程复制，拿到的是旧版本。

例外只有两类，都登记在 [`provenance.json`](provenance.json)：

- **拼接**（`files`）：一篇的代码被拆成几块讲，单块缺 import 或常量，按固定规则拼成完整文件；
- **独立项目**（`standalone`）：不属于任何一篇的完整工程。

## 机器清单说明

`provenance.json` 的字段：

| 字段 | 含义 |
|---|---|
| `version` | 契约版本，改语义时递增 |
| `files` | 拼接登记：目标文件 → 来源教程 + 块序号 + 拼接理由 |
| `standalone[].paths` | 独立项目目录前缀，必须以 `/` 结尾 |
| `standalone[].built_by` | 构建入口（如 CMakeLists.txt），`make strict` 会检查它存在 |
| `standalone[].verified_by` | 该项目的实测证据文件 |

## 校验链路

```
提取 → 溯源对账 → 静态检查 → 冒烟测试 → N 卡实跑 → 写入 expected_output.md
      （本机）    （本机）    （本机）    （唯一有效证据）
```

```bash
python3 scripts/build_from_blocks.py --check    # 篇目代码能否对上教程代码块
python3 scripts/build_from_blocks.py --check --strict   # 独立项目的构建入口是否存在
python3 scripts/static_check.py                 # 语法 / 依赖分层 / 硬件需求
python3 -m unittest discover -s tests -v        # 结构 + 骨架 + 溯源 + 静态 + 冒烟 + 包契约
make check                                      # 以上全部 + 派生文档是否过期
```

前几步只回答「文件对不对得上、依赖有没有越层」，冒烟测试才真正**执行**不需要显卡的脚本。
它们都**不验证数值正确性**——GPU 上的数字只有 `expected_output.md` 算数。
