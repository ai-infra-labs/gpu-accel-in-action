## 3. 手算核对

模型是 $y = x\sum_t a_t v_t = 11x$，目标 $2x$，所以单样本误差 $9x$，
平方误差 $81x^2$。样本为 $1..16$，$\frac{1}{16}\sum x^2 = \frac{1496}{16} = 93.5$。

| 量 | 手算 | 脚本输出 |
|---|---|---|
| Loss | $81 \times 93.5 = 7573.5$ | 7573.500000 ✓ |
| $\partial L/\partial a_t$ | $18 v_t \times 93.5$ → `5049`、`6732` | 5049.0、6732.0 ✓ |
| $\partial L/\partial v_t$ | $18 a_t \times 93.5$ → `1683`、`3366` | 1683.0、3366.0 ✓ |
| 更新后 $a_0$ | $1 - 10^{-5} \times 5049 = 0.94951$ | 0.94951 ✓ |

所以这组数字不是"跑出来大概是这些"，而是可以逐项验算的。

## 4. 断言清单

脚本靠这四个 `assert` 成立才算通过：

1. 三组划分各自覆盖全部 8 个 rank，且不重不漏。
2. 两个 DP 副本的样本集合没有交集（`len(set & set) == 0`）。
3. 每段梯度与"整模型一次算完"的参考值逐项 `isclose`（`1e-12`）。
4. 同步更新后，同一 DP 组的副本参数完全相同。

## 5. 这份数据不能说明什么

- **不是八卡实测**：没有 NCCL、没有通信、没有显存占用，它验证的是拆分口径。
- **不证明性能**：3D 并行的加速比取决于通信量与拓扑，本脚本一个字节都没传。
- **`T=2` 是简化**：真实 TP 还要处理 Attention 头切分、LayerNorm 复制等细节，
  这里只有一个逐元素乘加的玩具模型。
