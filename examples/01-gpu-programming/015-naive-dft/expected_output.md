判读方式：

- 分辨率是 $f_s / N = 8192/1024 = 8$ Hz，所以 440 Hz 与 1000 Hz **都落在桶中心**：
  `440/8 = 55`、`1000/8 = 125`，都是整数。这是刻意的——只有落桶信号，
  幅度才不会被频谱泄漏（leakage）削低，才能拿 1.0 与 0.35 去核对。
- 幅度标定用的是 $2/N$，且直流与奈奎斯特桶各乘 0.5。若峰值幅度只有预期的一半，
  先查这两个系数。
- `max_abs_error` 是和 `np.fft.fft` 比的。两者算法不同（朴素求和 vs 分治），
  差异来自浮点累加顺序，`1e-4` 量级属正常。

## 4. 这份数据不能说明什么

- **不能说明 GPU 比 CPU 快**：$N=1024$ 的朴素 DFT 只有 100 万次乘加，
  单核 CPU 也能在毫秒内做完。这条路径的价值是"讲清定义"，不是性能。
- **不能外推到 FFT**：$O(N^2)$ 与 $O(N\log N)$ 是两条算法路径，
  本篇的耗时不能拿来说明 FFT 库的表现。
