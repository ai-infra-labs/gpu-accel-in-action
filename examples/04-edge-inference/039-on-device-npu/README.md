## 为什么不放代码

文章讨论的是端侧执行路径的判断逻辑：CPU / GPU / NPU 不是同一种机器换三个名字，
模型要跑上 NPU，中间还隔着算子支持、图切分、数据搬运三层。全文 8 个代码块中：

| 类型 | 数量 | 内容 |
|---|---|---|
| mermaid | 2 | 执行路径与算子切分示意图 |
| text | 5 | 耗时拆分、数据量估算、时间线示意 |
| python | 1 | 12 行 `onnxruntime` 会话创建片段 |

唯一的 python 片段长这样：

```python
session = ort.InferenceSession(
    "detector.onnx",
    providers=["SomeSupportedAcceleratorEP", "CPUExecutionProvider"],
)
print(session.get_providers())
```

它有两个不能入库的硬伤：

1. `SomeSupportedAcceleratorEP` 是占位符，不是真实可用的执行提供者名称，
   具体名字取决于设备厂商，无法在此处写死；
2. `get_providers()` 只返回**注册**了哪些 EP，不返回**哪些算子被接管**，
   所以这段代码即使跑通，也得不出文章要的结论——那需要读图切分报告。

把这种片段抽成 `.py` 放进仓库，只会制造一个必然报错的文件。
