它验证了三件事，每件都配了 `assert`：

| 断言 | 说明 |
|---|---|
| `columns[0] + columns[1] == full` | 按输出维切，拼接即还原 |
| `add(rows[0], rows[1]) == full` | 按输入维切，部分和相加即还原 |
| `tp_result == reference` | 两层串接（列并行→行并行）与整模型一致 |

最后一行 `B=2 批次结果` 是防"批次维与特征维混淆"的对照：两个样本各自
独立过同一组权重，结果必须分别等于 `[12, 6]` 与 `[3, 1]`。

`[12, 6]` 就是 GPU 版 `tp_linear_demo.py` 应当打印的值——**这就是多卡结果的参照**。

## 4. 判读要点

- **两个 rank 切的是不同维度**：rank 0 拿 `WA` 的第 0–1 列、`WB` 的第 0–1 行；
  rank 1 拿第 2–3 列与第 2–3 行。切错维度会让 `all_reduce` 求和的不是同一批
  中间结果，数值会明显不对（不是精度问题，是结构问题）。
- **`all_reduce` 之后不再除以卡数**：TP 这里是"部分和相加"，不是"求平均"。
  与 DP 的梯度平均是两件事，别在同一段代码里混用两种语义。
- **最终偏置 `bb` 在 AllReduce 之后加一次**：如果每个 rank 都加一遍再求和，
  偏置会被乘上卡数——这是 TP 实现里最常见的 off-by-factor 错误。
- **层间没有 AllGather**：这里用的是"列并行 + 行并行"的成对结构，
  让中间结果可以留在各卡上，只在最后做一次 AllReduce。

## 5. 这份数据不能说明什么

- **不是性能测试**：1×4 的矩阵，通信与计算量都小到可以忽略。
- **不是完整的 TP 实现**：没有处理 attention 头切分、没有 sequence parallel、
  没有反向传播。
